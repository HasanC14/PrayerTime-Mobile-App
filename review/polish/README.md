# Native UI polish

Settings now uses grouped preference rows and an animated pill reminder switch. The reminder section contains only Prayer reminders and Reminder timing. The toggle and individual Home bells share contextual permission setup; notification settings and on-time reminder access are offered only when needed. There is no separate Notifications & sound row or test-reminder action. Reminder timing still controls minutes before the prayer period ends.

The toggle first requests notification access. Blocked access offers an explicit Open settings action. After notifications are allowed, Android precise-timing setup appears only if the native permission check returns denied. Later leaves allowed notifications enabled. Returning from settings refreshes access and completes only an outstanding user action. Granting precise timing changes reminder identities so previously inexact notifications are replaced. The Android-only local module in `modules/prayertime-reminder-access` reads permission status and opens package-specific system screens; Expo Go and older binaries skip unavailable native checks.

Location search and details live in a focused sheet. The main Home and Settings screens no longer display location-fix, cached-fix, or manual-source status labels. Detailed coordinates and accuracy remain available inside Location details.

Home, Calendar, Qibla, and Settings share flat themed backgrounds, consistent horizontal spacing, quieter card shadows, and persistent screen headers. The selected tab uses a subtle filled pill. Prayer rows place time ranges below names on compact screens or when the system font size is enlarged. Onboarding opens the city sheet directly when manual selection is chosen.

Sheets use a common header and simultaneous backdrop/slide transitions. Reduced motion removes those transitions. Closing dismisses the keyboard, and resizing the available viewport does not restart the entrance animation. Android back and backdrop dismissal still use the modal's close handler. Selection rows provide native haptic feedback where supported.

English, Bangla, and Arabic can be selected in Settings → Language and before location setup on onboarding. The selection is persisted. Shared localized text, pressable, and input components translate screen copy and accessibility labels; the source-message catalog includes dynamic templates. Bricolage Grotesque remains the Latin font, with locally bundled Noto Sans Bengali and Noto Sans Arabic for the other scripts. Prayer names, Hijri month names, dates, time ranges, duration labels, errors, privacy copy, and scheduled notification text are localized. Numeric entry accepts Bangla, Arabic, and Persian keyboard digits. The language does not alter prayer instants or date keys.

Arabic changes the root and modal layout direction immediately and updates navigation direction without forcing an app restart. Start/end spacing follows the chosen language, while physical compass directions remain fixed. Bangla places longer prayer time ranges below the prayer names. The custom switch has a 56 × 32 pill track, an outlined off state, a filled on state, a 170 ms animated thumb, reduced-motion support, keyboard interaction, haptics, and checked/busy/disabled accessibility state. Its thumb movement is reversed in Arabic.

Notification identities include the language. A language change replaces pending notifications in the new language, and repeated reconciliation retains them without duplicates. The Android channel name and description are also localized. System permission screens remain controlled by the phone.

The vector brand mark is shared by onboarding and the animated splash. The updated Home card uses a prayer icon and timing details; see `review/features/README.md`. Launcher assets have separate opaque, adaptive, and themed versions with safe padding; see `assets/icons/README.md`.

Validation includes TypeScript, ESLint, all 69 regression tests, Android bundle export, Android native prebuild/autolinking, launcher mask previews, and the browser checks recorded in `browser-checks.json`. `reminder-flow-checks.json` records tests of the actual application hook running in React with mocked native adapters: denial, returning from settings, Later, selected prayers, precise timing, and cancellation. Screenshots cover light and dark appearance and widths of 390 and 320 pixels. Location search responses in the browser interaction checks are mocked.

Language checks and screenshots are recorded in `languages-report.json`, covering immediate language changes, persistence, all four screens at 390 and 320 pixels, dark appearance, localized settings sheets, local numeral entry, onboarding, and manual setup. `toggle-report.json` covers animation, state, keyboard access, disabled interaction, and RTL movement using the actual switch component. `notification-languages-report.json` covers the actual notification service against mocked OS/storage adapters, including language replacement, repeated reconciliation without duplicate requests, and cancellation.

No Android device was connected. Compiling the new native module locally was interrupted by insufficient disk space while Gradle downloaded build dependencies. The temporary Gradle cache was cleared; native compilation remains unverified. Native keyboard behavior, actual permission dialogs, haptics, launcher presentation, and TalkBack still need device verification with a rebuilt APK. Browser checks and native resource generation do not establish device-wide compatibility.
